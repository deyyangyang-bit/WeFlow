## 1. 背景与问题

AI 在产品里的角色已从「全天候实时识别」修正为「**早间简报 + 按需分析 + 手动按钮**」：白天销售自己看得见客户消息，AI 再报一遍是与人抢活；原实时链路（方案 §3.2）整套删除，5 工作日观测期取消。论证见定位修正层，本文档不重复。

当前要解决的问题：

- **开工简报是最破的一块**：六种空态只实现 2 个通用空态，新账号显示「🎉 今天全部跟完了！」——把「什么都没有」说成了「全部完成」，语义相反；
- **AI 仍在白天自动干活**：`salesFollowUpService` 自动扫聊天抽承诺建卡、`insightService` 自动写 archive 评论并发通知、启动预热前 8 条——与新定位直接冲突；
- **想用的时候没有入口**：销售想让 AI 看某个客户，没有任何手动触发方式；
- **简报准确性无保障**：游标在内存（`insightService.ts:1585` 的 `lastSeenTimestamp`），重启即丢，早上那次简报要么漏要么重扫。

## 2. 产品定位与目标

AI 只做三件事：

| # | 做什么 | 触发方式 |
|---|---|---|
| 1 | 早上替销售回忆 + 排序：上次工作以来发生了什么、今天该跟谁 | 每天第一次打开，自动 |
| 2 | 对某个客户做一次识别 | 手动按钮「AI 识别这个客户」 |
| 3 | 全局重扫一次 | 手动入口「重新生成简报」 |

**不再做的**：上班时间持续扫描、实时生成见解、实时报警、自动建卡、自动写评论、启动预热。

目标：

- 简报六种空态语义全部正确，任何失败/额度阻断不得显示为「无风险/无需跟进」；
- 关闭全部白天自动链路后，销售手动发起的识别能力不缺失（中间态不允许「自动的关了、手动的没上」）；
- 每次 AI 调用可归因（谁触发、什么目的、花了多少），费用可预测（上限粗估起步 + 80% 预警）；
- 不新建第二套客户、待办、判断事实源；不修改正式业务字段；复用既有 `ai_detected` trigger 与抽取逻辑。

## 3. 术语与数据契约

- 字段语义与对象映射以 `docs/DATA-CONSTITUTION.md` 为唯一事实源（SSOT），本文档不新建表、不新建 trigger 类型；
- `trigger_type = 'ai_detected'`：来源能力标记，含义升级为「AI 识别产出，且由人触发」；历史自动扫描存量的辨识依靠 `created_by`；
- **`created_by` 记操作的销售本人**（2026-09-12 拍板）：trigger 记来源能力，`created_by` 记触发人，两者不冲突；手动识别产出不得写 `created_by: 'ai'`；
- 用量账本 `purpose = 'manual_identify'` 记手动识别，与后台简报调用可区分；
- `follow_up_task.trigger_type` 的数据库默认值由 `'ai_detected'` 改为中性值（如 `'unknown'`）或非空必填——当前默认值会让任何漏传的新调用方被静默误标为「AI 识别」；
- 识别结果写入 `customer_judgment`（经现有合法写入者）；有实质进展时生成/更新 `follow_up_task`；**不修改正式业务字段**（产品内 AI 三档纪律：合并/归属变更/发布永不自动执行）。

## 4. 用户流程

### 4.1 早上开工（自动）

1. 销售每天第一次打开今日行动页；
2. 300ms 内显示页面框架与状态；业务库就绪后 2 秒内展示本地事项或已有快照；
3. 后台异步生成简报，期间展示已有事项及「正在梳理 N 个会话」与覆盖区间；
4. 完成后按六态之一呈现（§6.1）；超时保留事实列表并显示「分析仍在进行/部分未完成」。

「每天第一次」按**自然日 + 账号**双键判定并幂等：同日重复打开不重复生成；跨天第一次打开才触发新一轮。

### 4.2 单客户按需识别（手动主路径）

1. 销售在客户 360 / 客户详情页点「AI 识别这个客户」；
2. 系统先比对游标/最新消息时间：**无新消息则不发起模型调用**，直接显示「距上次识别无新消息」；
3. 有新消息则发起识别（单飞，§6.2 状态机），结果显示「刚刚更新」；
4. 产出落到该客户的判断/待办，页面就地可见。

### 4.3 全局重新生成简报（手动补充路径）

1. 销售在今日行动页顶部点「重新生成简报」；
2. 按简报同一管线重扫（⌈活跃会话数/20⌉ 轮调用）；
3. 展示复用简报六态；扫到一半额度耗尽时显示「部分未完成」+ 已有结果 + 未处理数量，不得显示「全部完成」。

### 4.4 额度不足

1. 任一入口触发额度不足时，明确阻断并说明原因，不静默；
2. 阻断提示中带「提高当日上限」入口（设置页）；提额动作记审计；
3. 手动按钮调用计入当日上限。

## 5. 功能需求

### 5.1 早间简报补全（第一优先）

- 六态全部实现（§6.1），替换「🎉 今天全部跟完了！」等错误文案；新账号空态提供导入/绑定客户、创建待办入口，**不调用 AI 凑摘要**；
- 首屏时间预算：300ms 框架、2s 本地内容、>2s 明确加载态、10s 重试与错误说明，**不能伪装为空**；
- **持久化游标**（W1b 核心）：记录「上次处理到哪」，按账号持久，重启/关机后简报不漏扫不重扫；替代内存 `lastSeenTimestamp`；
- 结果共享：同一批材料被简报与手动识别等多个下游消费时复用，不重复调用；
- 首轮截断：首启最多回看 7 天；每轮最多处理 20 个会话；
- 简报保持事实版、幂等；覆盖区间（coverage）从静态文案改为真实游标区间（W3b）；
- 「可选 AI 整理」默认关闭（额度默认 ¥0），`parseAiDigest` 在关闭时不发起调用。

### 5.2 「AI 识别这个客户」按钮

- 入口：客户 360 / 客户详情页头部操作区，主按钮；
- 复用 `salesFollowUpService` 的抽取逻辑（去重、置信度、`due_days`、优先级）**原样保留，只换扳机**：由定时器改为手动；
- 触发即调用前判定（§4.2 第 2 步）；产出契约见 §3（`ai_detected` + `created_by` 记销售 + `purpose: manual_identify`）；
- 输入上界：单次最多处理该客户最近 N 天 / 最大 M 条消息（N、M 为实现参数，须写明）；「1 次调用」的成本声明只在该上界内成立；W1b 持久游标未落地前，按钮按降级形态提示「当前为全量重扫」；
- 状态机与交互口径见 §6.2，与修正层 §4.4/§4.7 一致；
- 明确不做：不自动打电话或对外发消息；不因一次识别认定成交/流失；不因按了按钮把客户加入/移出任何名单。

### 5.3 「重新生成简报」全局入口

- 入口：今日行动页顶部（简报旁），次级入口；
- 与早间简报同一管线、同一六态展示；额度中断按「部分未完成」处理（§4.3 第 3 步）；
- 命名即定位：它是简报的手动版，不叫「重新梳理」。

### 5.4 关闭白天自动链路（R，与 §5.2 同批不可拆）

- 删除自动评论链路（`insightService.ts:506-519 → 1546+ → 1926-1928`）：不再自动写 archive 评论、不再自动发通知；
- 删除启动预热前 8 条（`salesActionEngine.ts:519-520`）；
- `salesFollowUpService` 自动扫描（`:326-353`）关闭定时触发，抽取逻辑保留给按钮与简报调用；
- **复核两层为实时链路服务的刹车**：DB 防抖 2s（`insightService.ts:506-519`）与每会话冷却 120min（`:1556`）——实时链路删除后其存在理由消失，简化或移除在本批一并决断；`:510` 的 `if (this.processing) return` 静默丢弃事件属既有缺陷，不得原样保留；
- 范围纪律：R 只关链路与预热；「识别 vs 文案」拆分（W1a）是另一个交付块，两块都会改 `insightService.ts`，接受摸两次，不互相越界。

### 5.5 用量、价格与上限（够用即可，不卡交付）

- 打标补齐：`sla2`、`payment` 接线、`groupSummaryService` 旁路调用纳入账本；其余未打标点按清单补齐；
- 产出 AI 调用入口/消费清单文档；价格表用**官方刊例价**（静态输入）；
- 日上限 + 80% 预警保留为常规配置项，取值**粗估起步、按实际用量调整**，不需要观测期；粗估必须按「简报每天 1 轮（⌈活跃会话数/20⌉ 次调用）+ 按需按钮」估，不得按「每天一两次」估；
- 达到上限不得静默超支，被阻断的事件计入覆盖缺口展示。

### 5.6 技术支撑（引用，不进验收）

以下在收口计划 §4.3 排期、本文档不重复定义，但 §5.1/§5.2 依赖其完成：F1 嵌套排队收尾（`enqueueSalesTask` 只留最外层入口，被排队函数内部绝不再 enqueue——死锁红线）；F3 切号失效收尾（在途请求取消、msgCache 复位、切库失败阻断报错）；W1a 识别与文案分离（识别不再从文案正则解析，文案失败不拖垮识别）；W2b 事项身份与口径对齐。

## 6. 交互契约

### 6.1 简报六态

| 状态 | 展示 |
|---|---|
| 新账号，无聊天也无任务 | 「暂无客户沟通和待办」，提供导入/绑定客户、创建待办入口，不调用 AI 凑摘要 |
| 无聊天但有 CRM 事项 | 展示业务事实待办，标注无聊天依据 |
| 有待处理数据 | 展示已有事项及「正在梳理 N 个会话」，标明覆盖区间 |
| 全部覆盖且无有效待办 | 「当前没有待跟进事项」，显示检查截至时间 |
| 分析失败或额度阻断 | 显示已有事实、未处理数量及原因，**不显示「无风险/无需跟进」** |
| 只有旧快照 | 显示原生成时间和更新状态，禁止冒充今日最新结论 |

「正在梳理」超过 60s 目标时保留事实列表并显示「分析仍在进行/部分未完成」，不阻塞操作。

### 6.2 识别按钮状态机

| 状态 | 表现 |
|---|---|
| 空闲 | 「AI 识别这个客户」可点击 |
| 进行中 | 「识别中…」，**两个入口的识别按钮全部禁用**（单飞作用域为全局） |
| 完成 | 结果显示「刚刚更新」，按钮回到空闲 |
| 无新内容 | 调用前判定，直接显示「距上次识别无新消息」，**不发起模型调用** |
| 失败 | 明确报错，不静默 |
| 额度不足 | 明确阻断 + 提额入口（§4.4） |

「重新生成简报」的展示复用 §6.1 六态，不另建状态机。

## 7. 验收标准

### 7.1 简报

- 六态逐一可复现：新账号空态不显示「全部跟完」类文案、不发起 AI 调用；失败/额度阻断态显示原因与未处理数量；
- 首屏满足 300ms/2s/10s 预算（标注测试硬件、库规模与样本，不宣称未实测达标）；
- 杀进程重启后，简报从持久游标续扫，不漏不重（构造重启前部分处理的场景验证）；
- 同日重复打开不重复生成；跨天第一次打开触发新一轮；
- 首启截断 7 天、每轮 ≤20 会话生效；超过 20 个候选的必做事项不因截断消失。

### 7.2 按钮

- 「无新内容」场景不发起模型调用（账本无记录），界面直接提示；
- 任一识别进行中，两个入口按钮均禁用；
- 产出的 `follow_up_task`：`trigger_type='ai_detected'`、`created_by` 为当前销售、账本 `purpose='manual_identify'`；
- `trigger_type` 默认值改为中性值后，漏传调用方不再被标为 `ai_detected`；
- 抽取逻辑行为与改造前一致（去重、置信度、`due_days`、优先级回归通过）；
- 失败、额度不足两态均有明确展示，无静默路径。

### 7.3 关闭自动链路

- 全天运行不产生任何自动评论、自动通知、自动建卡、预热调用（账本佐证：无后台 `purpose` 记录）；
- 关链路与按钮上线同批交付，无中间态；
- 防抖/冷却复核结论记录在案；`if (this.processing) return` 的静默丢弃有明确处理（改为排队/拒绝并提示，或论证保留理由）。

### 7.4 用量与费用

- 账本覆盖全部调用点（含 sla2/payment/原旁路），缺失 token 记 null 不记 0；
- 清单文档与刊例价价格表入库；每日费用可按 `purpose` 拆分展示；
- 80% 预警与硬上限生效；上限被提额时记审计；被阻断事件计入覆盖缺口。

### 7.5 基线

- `npx tsc --noEmit` 0 错误；收口计划 §1.1 基线测试全绿；新增测试纳入 HANDOVER §11 基线命令；
- Windows 打包态未实测时必须如实标注，不得以本机启动代替。

## 8. 期次划分

与收口计划 §4.3 排序一致（`F1/F2/F3 → W2b → W3a/W1a → W1b → W3b/(R+按钮)`），产品交付视角：

| 期次 | 内容 | 说明 |
|---|---|---|
| 第一批 | §5.1 简报六态 + 时间预算 + 持久游标 | 用户初衷的正主 + 当前最破的一块；持久游标是简报准确性的地基 |
| 第二批 | §5.2 按钮 + §5.4 关闭自动链路 | **不可拆**：自动的关了、手动的没上 = 纯能力倒退 |

容量超预期时：W1a（技术支撑）先让位，简报（第一批）绝不让。

## 9. 风险与防范

| 风险 | 防范 |
|---|---|
| 游标未落地时按钮退化为全量重扫，成本失控 | 输入上界（N 天/M 条）+ 界面降级提示；第一批先交持久游标 |
| 「部分未完成」被读成「全部完成」 | 六态与全局入口均强制展示未处理数量；验收 7.1/7.2 覆盖 |
| 关自动链路后销售感觉「AI 没用了」 | 按钮同批上线；标签语义升级为「是我让它识别的」 |
| 承诺当天捕获能力下降（自动扫描已关） | 早间简报批量补扫不丢；观察「当天说当天办」比例，显著则加第二个自动时点（如午间），不回全天候实时 |
| 上限粗估被简报批量打穿 | 按 ⌈活跃会话数/20⌉ 估简报成本；80% 预警提前暴露 |
| 同一材料简报与按钮重复付费 | 结果共享（W1b）；按钮调用前判定无新不调 |
| 改 `insightService.ts` 多块并发越界 | W1a 与 R 范围纪律：各改各的，接受摸两次 |
