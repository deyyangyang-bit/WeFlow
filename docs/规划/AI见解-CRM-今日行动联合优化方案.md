## 1. 目标与边界

用户目标：销售开工时看清上次工作以来客户的状态、今天该跟进谁、哪些适合电话沟通，以及到期事项；白天少打扰，关键业务仍自动识别。费用优化以缓存输入、未缓存输入、输出约 1:1:1 的用户观察为线索，先测实际归属，不预先承诺节省比例。

保留聊天驱动建档、有效触达判断、认领满 24h 首次分类、信息缺口反问卡、业务事件触发档案更新、付款/风险识别、交付售后和人工确认。停止把“成功生成一句评论”作为其他能力运行的前提。

不新建第二套客户、商机、待办或判断事实源；不将 AI 阶段信号直接写成正式成交；不自动打电话或对外发消息。已有告警评测门槛不因改造放宽。

### 1.1 冲突仲裁：识别、出卡、通知分开决定

优先级：在授权、证据和数据正确性约束内，关键事件及时识别和进入行动列表优先于成本优化；是否弹窗单独按紧迫性判断。不能以减少打扰为由把当天采购进展延迟至次日。预算硬上限仍是执行边界，达到上限不得静默超支，也不得声称仍保证召回。

“购买进展”候选包括：新增/改变型号或数量、报价异议或接受方案、明确推进订单/合同/付款、采购时间或决策流程变化、明确取消或选择其他供应商。该目录是判定与评测范围，不是唯一关键词过滤器。

本地规则识别显式线索并确定调度优先级；基础批次分析结合上下文判断语义、返回证据及待核验事项；正式字段变化由原业务写入者按权限裁决。短回复、歧义或证据不足时，偏向保留待核验候选，不直接认定成交/流失，不自动弹窗，也不加非客户黑名单。所有实质客户新消息仍进入基础处理，不能只处理命中规则的消息。

| 冲突场景 | 必须采取的动作 |
|---|---|
| 新采购进展与文案节省冲突 | 优先识别、更新判断/提案及相应行动；省去评论，不省掉识别 |
| 已识别进展但无紧迫期限 | 当天及时进入行动列表，不强制弹窗，不等晨间摘要 |
| 明确当日回电、迫近期限或已批准告警 | 优先核验；符合原通知契约才通知，普通待核验候选不冒充告警 |
| 不确定是否重要 | 保留候选及依据，进入待核验；不得写为已确认事实 |
| 模型不可用、队列超时或预算耗尽 | 展示处理缺口、保留规则待办和人工查看入口，记录待补处理范围 |

每次优先级提升、降级、跳过、超时、预算阻断均记录账号、事件/批次标识、判据版本、原因、时间和后续状态；无需保存完整聊天。召回、进入列表的时效与通知准确率分别验收，不用“最终识别到了”掩盖当天漏跟进。

## 2. 当前关联与问题

| 模块 | 当前源码中的关联 | 优化重点 |
|---|---|---|
| insightService | 活跃/沉默触发；写 archive 见解、summary judgment；阶段信号、CRM 导入与 enrich；沉默扫描还挂回填和催办 | 分离调度、业务识别、用户文案；未知不能直接等同非客户 |
| crmEnrichService | 读聊天、近 10 条见解和关系画像，再调用 AI 提取字段 | 减少二次推理；旧 AI 结论只作待验证背景，不能成为新增事实的唯一证据 |
| salesActionEngine | 规则建卡、阶段识别、高优先级前 8 条分析预热；统一流合并任务和告警 | 取消默认文案预热；保持必要识别；读取与扫描分开 |
| customerCurrentView | 只读 customer_judgment 的最新四类判断与当前状态 | 保持纯投影；新生产链继续通过合法写入者落 judgment |
| morningDigestService | 统一流 top 10 → 选 3；08:05–08:35 调度；快照落 report_snapshot | 升级开工简报，补开机触发、事项上下文、覆盖范围和处理状态 |
| 首次分类/有效触达 | 专门服务和证据/确认流程 | 保持自动入口，材料可共享，专门业务判断不能未经评测合并掉 |
| 付款、风险、售后 | 已有识别、承诺登记、到期扫描、生命周期卡及关闭钩子 | 复用原事实和关闭条件，简报不另建重复待办 |
| 重要提醒 | accountScope 过滤；白名单告警进入统一流 | 区分已读和已解决，窗口过期不等于事项完成 |

统一流当前主要按 session_id 聚合，并非按商机事项聚合。手动任务存在同键覆盖路径；普通客户完成入口按会话批量关闭待办。普通规则任务组装还可能把包含金额/型号的标题替换成泛化理由。上述问题需要在汇总简报前修正。

## 3. 产品体验

### 3.1 当天首次打开：开工简报

复用今日行动页面顶部，不新增独立工作台。当天第一次打开且当前账号业务库就绪后触发；已有当天快照先展示。定时入口与首次打开共用幂等入口，不要求 8 点在线。

覆盖：上次成功处理以来的新聊天、今日到期/逾期任务、有效报价跟进、付款承诺、交付/回访/设备周期事项。周末和离线期间不以“昨天”截断。首次启用默认处理最近 7 个自然日（含当天）的聊天；未完成、逾期及当前有效业务事项不受 7 天限制。既有游标恢复处理不套用首次 7 天截断。历史补齐每轮最多 20 个会话，可被实时任务抢占；更早上下文按事项需要补读，用户主动批量历史分析另计预算。显示待处理会话数与覆盖区间，不全量扫历史。

分三组：今天必须处理、建议优先跟进、状态更新/暂不行动。首屏默认展示 5 个事项（不是 5 个客户），先必做、再建议；不足不凑数，其余显示数量并可展开。状态更新默认折叠。现有 top 10 选 3 是旧实现，不是新目标；事实事项完整分页，AI 整理初版最多取 20 个优先候选，未入 AI 候选不影响必做事项展示。

每项字段：客户、具体业务事项、进展、尚未解决的问题、今天的动作、建议渠道及理由、期限、证据入口、数据截至时间、处理状态。金额和日期直接取合法业务事实，缺失不让模型补。

示例（虚构）：客户询问两台搬运车含运费价格，地址未确认 → 微信确认地址后补报价；客户要求今天回电且交期未定 → 电话确认型号与交期。单纯沉默不能推出需要电话沟通。

### 3.1.1 首屏预算与空态

首屏不等待扫描、模型或业务库初始化：页面进入后 300ms 内显示框架/状态；业务库就绪时，2 秒内展示本地事项或已有快照（Windows 试点目标 P95）。读取超过 2 秒显示明确加载状态，10 秒仍不可用提供重试及错误说明，不能伪装为空。

首次打开仅发起异步生成命令；列表读取保持纯读。后台 AI 整理目标 60 秒内完成，超时保留事实列表并显示“分析仍在进行/部分未完成”，不阻塞操作。上述为上线验收目标，须标注测试硬件、数据库规模和样本，不宣称当前已达到。

| 状态 | 展示 |
|---|---|
| 新账号，无聊天也无任务 | “暂无客户沟通和待办”，提供导入/绑定客户、创建待办入口，不调用 AI 凑摘要 |
| 无聊天但有 CRM 事项 | 展示业务事实待办，标注无聊天依据 |
| 有待处理数据 | 展示已有事项及“正在梳理 N 个会话”，标明覆盖区间 |
| 全部覆盖且无有效待办 | “当前没有待跟进事项”，显示检查截至时间 |
| 分析失败或额度阻断 | 显示已有事实、未处理数量及原因，不显示“无风险/无需跟进” |
| 只有旧快照 | 显示原生成时间和更新状态，禁止冒充今日最新结论 |

### 3.2 白天：后台必要更新，前台安静

普通连续消息按批处理必要识别，不逐条写关系评论。初始建议静默窗口 90 秒、最长等待 5 分钟；参数通过试点校准。明确要求当日回电等时效候选优先处理，但规则不是唯一识别门槛。"可以/就这个"必须结合前文，不能直接过滤。

处理时限从本机检测到事件开始计，程序关闭期间不承诺实时：普通批次从第一条未处理消息起最迟 5 分钟封批；队列等待目标不超过 60 秒，单次模型任务目标不超过 60 秒；成功结果落库后 5 秒内更新列表。因此普通路径目标在 7 分钟 5 秒内可见，不延迟至次日。每个阶段超时显式记为时效违约并显示积压，禁止靠反复延长定时器隐藏。

显式时效候选最多合并 15 秒，进入高优先级队列（不抢断正在写库的事务）；从检测至核验结果可见目标 2 分钟内。未被规则命中的重要语义仍由普通批次兜底，不能承诺所有重要事件都达到快通道时限。通知必须满足证据和原告警/任务通知契约。

阶段变化、新报价、成交登记、回访完成、沉默跨阈值仍触发相应档案提案。无新消息也可能有有效业务事件；同一阈值事件只处理一次，不能每轮轮询重析。

销售点击“准备跟进”时，按当前具体事项生成话术或电话要点。已有输入版本匹配的结果复用；有新事实时显示待刷新。普通打开页面不隐式调用 LLM。

### 3.3 完成与反馈

按 taskId/业务事项处理，不按客户一键完成所有任务。客户级批量操作需要明确列出勾选事项。已读提醒不等于完成；付款核对、签收等继续走各业务确认入口。

简报快照保留生成时依据，展示时叠加当前任务状态；完成项移出待办区域但历史可回看。状态更新不重写整份 AI 简报。电话跟进完成可记录结果，派生更新沿用已有事件链。

## 4. 数据与处理流程

1. 入口捕获账号范围、库身份/切换代次、会话、消息游标或业务事件版本。
2. 本地收集批次：新增消息、必要前文、已确认 CRM 事实、有效任务、带来源的既有判断。不使用昵称猜测账号或跨客户合并。
3. 对材料做变化检测；相同输入与任务版本复用结果。分析范围不足时补读历史，而非强行仅看新增一句。
4. 按需要路由：基础需求/阶段信号可共享提取；首次分类、有效触达、付款承诺等保留专门契约。一个事项不经过所有模型任务。
5. 经现有合法写入者更新 judgment、提案和业务登记；跨库失败记录消费状态并幂等补偿，不宣称全局事务。
6. 规则引擎根据事实生成或关闭 follow_up_task；只读组装客户/事项视图。
7. 开工简报复用视图，必要时一次短文本整理；大批候选先排序分页，禁止无限扩大的单次请求。

客户聚合采用账号范围和已核验的 customer/account 映射；会话标识作为来源。事项保留 kind + 原始 ID。已有 source_id 必须与 trigger_type 一起解释，不能把不同表相同数字合并。未绑定会话的 CRM 客户及售后任务也必须显示，不能套用“无聊天/已成交就过滤”的规则。无法归属商机的提醒暂挂客户，不让 AI 猜某一订单。

继续使用 customer_judgment、follow_up_task、report_snapshot、已有 CRM 表与提案/审计事实。运行进度、消费状态、用量记录、按需话术/电话要点缓存若无合适现有载体，实施时先登记 DATA-CONSTITUTION 与 API 契约再建，不挤占业务字段、不另造事实表。

### 4.1 按需生成缓存契约

优先核查现有任务 analysis 等载体能否承载缓存及版本元数据；禁止把历史 analysis 当当前判断事实源。无法满足时先入宪登记专用派生缓存，不另建客户事实。

缓存键至少含：账号范围、业务库代次、事项类型与 ID、输入材料指纹、已确认业务事实版本、模型/提示词/输出模式版本。保存结果、生成时间和证据引用。新消息、事实更新、事项关闭、证据不可用、账号切换或相关版本变化使缓存不可复用；兜底最长复用 24h。命中时仍校验事项状态。历史可读不等于可以当最新话术直接使用。

## 5. 消耗优化

### 5.1 先观测

分别标记 insight、stage、enrich、first_classify、sla2、payment、action、digest 等调用目的。记录模型、提示词版本、触发原因、输入/缓存输入/输出/推理 token（接口有则记录）、耗时、重试和结束原因。缺失 usage 记 unknown，不记 0；推理 token 若包含在输出内不能重复计费。

用量按账号隔离，不保存密钥或完整聊天调试日志。模型单价经实际服务商配置/核实后计算费用，token 数量比例不当作费用比例。

### 5.2 缓存与输出

固定 system 前缀、输出模式、工具定义与材料排序；变动事件和时间后置。不同客户的聊天不假设可共享缓存，不为凑缓存故意扩长提示词。同一客户稳定上下文与增量输入的取舍，通过真实 cache usage 对比验证；更短的增量输入可能比更多缓存 token 更便宜。

短摘要可先试正文 60–100 字、短任务 256–512 输出 token；结构化提取初始 800–1200，字段完整性优先；深度分析独立配置。上述为试验值，不是通用生产定值。支持时简单任务关闭/降低思考；检查 finish_reason 和 JSON 完整性，截断只允许有限扩预算重试，不推进成功游标。

### 5.3 去重与预算

同一账号/会话/输入版本/任务版本单飞。成功、无有效变化、失败分别记录；SKIP 也推进已判断范围。失败有限重试；新消息形成下一批，旧批不覆盖新结果。全天 24h 去重仅适用于重复事项，不阻挡当天新的购买进展。

后台预算优先保障必要识别，先延后可选文案和历史补齐。关键任务若也无法执行，明确显示待处理/失败数量并补跑，不把未分析显示成“无风险”。手动请求独立显示成本/额度状态，不暗中超预算。

### 5.4 预算执行参数与上线条件

不凭空把固定金额写成业务已接受的日额度。每账号必须具备以下配置，币种统一 CNY，按 Asia/Shanghai 自然日结算；修改留审计：

| 参数 | v0.2 决策 |
|---|---|
| 可选后台文案日额度 | 默认 ¥0：自动 AI 润色/文案预热关闭，开工简报先用规则模板；手动分析不属于此子额度 |
| 全部 AI 调用日硬上限 | 数值待实际模型价格及至少 5 个完整工作日基线确定；现有调用记账观测先行，新调度器正式启用前必须配置正数，不允许空值被解释成无限额度 |
| 必要识别费用预警 | 日总上限的 80%，预警并暂停可选文案与历史补齐，优先保留实时必要识别 |
| 手动请求 | 纳入总上限；不足时明确阻断或由用户显式提高当日上限，不自动豁免 |

这是明确的上线阻塞项：总上限金额未确定或模型价格不完整时，仅做现有链路观测，不启用新的自动调用策略。不能把“记账已实现”当成“预算已可执行”。采集基线后同时报告账号规模、必要识别 P95 日费用及超额积压模拟，再决定每账号额度；不以任意金额换取表面可实现。

发请求前按实际输入估计、输出上限和保守未缓存价格预留额度；并发请求统一扣预留，实际 usage 返回后结算。未知 usage 暂保留保守估计并标记待核对，不释放成免费；支持多轮的任务逐次预留。重试同样计费并受上限约束。无法估计计费上界的模型不能纳入硬金额预算上线范围。

额度耗尽后不再派发新 AI 请求；在途已预留请求可完成。实时必要识别保留积压与人工查看入口，次日/显式提额后先重评事项有效性再补处理。记录这是召回/时效的降级，不能把预算阻断样本排除出质量报表。

## 6. 账号隔离与调度可靠性

每个异步任务开始和写入前校验账号与库代次；切号取消/失效旧任务、清理计时器及前端缓存，旧响应不能写进新库。切库失败阻止业务访问并明确报错。处理游标、简报、用量、内存缓存均按账号隔离。

多微信号按 PRD 保留：各数据源分别处理，跨号客户合并只使用已核验身份关系和权限。初版明确为“当前微信账号简报”，页头显示来源账号。同一客户在 A、B 两个微信号都有聊天时：A 页只显示 A 来源事项，切到 B 只显示 B 来源事项；不在一个当前账号简报里显示其他账号那条，也不按同名合并。切号时旧简报立即失效，不等待新内容才清掉。

跨号汇总属于后续独立范围：仅在权限允许且 customer_identity 已确认归并时，客户可一组展示并标注各微信来源，事项仍分别处理；未确认身份关系则分开显示。初版不提供跨号完整性承诺，界面标明“仅当前账号”。

读取统一信号改为纯读；扫描与摘要调度由最外层队列入口协调。当前晨间调度入队后调用的 getUnifiedSignals 内仍有入队路径，实施需消除嵌套队列死锁风险，不能直接沿用组合。

原子落盘、失败留证、重启续处理。此次方案不重新导入用户已归档的混合业务库；历史归档与新分析链迁移分开。

## 7. 工作流、硬依赖与交付门槛

取消整包 A→B→C→D→E 串行。以下是交付关系，不要求同批发布；列出的独立项可分别完成，不必等最重的模块。

| 编号 | 交付 | 硬依赖 | 上线门槛 |
|---|---|---|---|
| F1 | 消除嵌套排队、拆开读取和扫描 | 无 | 不死锁；纯读不发模型请求；旧扫描行为有回归测试 |
| F2 | 入口/消费清单、用量与价格观测 | 无 | 功能归因、unknown 用量语义正确；不调整业务触发 |
| F3 | 账号绑定、切号失效、前端清缓存 | 无 | 在途任务不串库；失败关闭业务访问 |
| W1a | 见解职责拆分、必要识别独立入口 | F2 的依赖清单、F3 | 各下游独立工作；不依赖文案生成成功 |
| W1b | 消息批次、游标、结果共享与模型预算 | W1a、F1、F2 完整观测 | 本方案时效、召回、成本、预算与持久化契约通过 |

### 7.1 灰度与回退契约

按账号选旧/新生产入口，同一事件只允许一个正式写入路径。比较测试用离线样本或影子只读输出，不双倍生成提案和任务。上线前记录旧行为基线与明确保留的缺陷修复清单。

回退先停新任务派发、使在途新任务失效并保存处理范围，再恢复兼容旧入口。新旧去重适配必须识别已消费事项，不能简单清空游标重跑。保留已生成事实、提案和审计；新增字段兼容旧读取。回退指同一构建中的功能路由切换，不默认允许安装任意旧版本读取新库。

“恢复原行为”限定为未刻意改变的业务契约：原识别入口、字段权限、人工确认、通知开关与旧页面可用。账号隔离、死锁和误关闭修复不回退。缓存可失效重建，事实不能撤销或丢失；回退不自动恢复已归档的混合数据。

## 8. 验收场景与指标

- 连发四条消息只形成一个主分析批次；模型专门核验的额外请求单独归因。
- 客户“就这个”确认方案，结合上下文不漏；上午询价下午决策不被全天冷却压掉。
- 群发/系统消息不冒充客户；资料不足不加非客户黑名单；历史 AI 见解不自证事实。
- 认领满 24h、有效触达、沉默跨阈值、回访完成、付款与交付周期均独立工作。
- 两个商机、三条待办独立完成；报价回复后旧提醒关闭；无聊天的交付事项可见。
- 周末后首次开机补未处理区间；当天重复打开复用；模型失败仍有事实待办，并注明未分析覆盖。
- 分析中切号、请求迟到、重启、归档重建库、跨库写入失败均不串数据、不无限重试。
- 采用率/漏识别率与原基线对比；重要事件召回不得因降本退步，判定评测沿用 PRD 门槛。
- 首屏验收：新账号空态、无聊天但有业务事项、旧快照、模型超时、数据库未就绪分别测试；满足 §3.1.1 时间预算，首次生成不阻塞页面。
- 固定事件集分别量化识别召回、进入列表时延、通知准确率；普通及快通道满足 §3.2 目标。下午确认采购当天进入列表，不等次日；不确定事件保留待核验，不能自动成交或弹窗。
- 预算验收：可选额度 ¥0 时事实简报可用且无自动润色请求；80% 预警、硬上限、并发预留、未知 usage、重试、跨日与手动提额均有测试；被预算阻断的事件计入覆盖缺口及降级报表。
- 回退演练：同一输入集下，新路径处理一部分后切旧路径；恢复未改变的旧业务行为，已生成提案/待办不重复、不丢失，旧页面正常读取；在途结果不迟到落库，安全修复保持有效。另测试切回新路径可以续处理。
- 双账号同客户：当前账号页只显示自身来源；切号无旧条目闪回；话术缓存不跨号/跨事项复用，事实及提示词版本变化后失效。
- 首次 7 天外旧未完成任务仍展示；既有游标跨周末补齐不丢；首屏 5 项与全部展开一致；超过 20 个候选的必做事项不因 AI 截断消失。
- 展示各功能每日费用、缓存命中率、输出/推理占比、重复请求、摘要使用和待办执行数据。不把历史行动卡 0.6% 当作 AI 见解单独采用率。
