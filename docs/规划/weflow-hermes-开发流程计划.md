## 1. 开发模式：一个人 + 一组 AI Agent

| 角色 | 谁 | 干什么 |
|---|---|---|
| 产品负责人 | 你 | 需求拍板、任务下发、DoD 验收、每日进度确认、业务规则答疑 |
| 主开发 Agent | AI（见 §3 模型分工） | 计划、编码、测试、提交 |
| 业务验收人 | 销售主管 | Phase 0 数据宪法评审、评测集标注、试点反馈 |
| 试点用户 | 1-2 名销售 | Phase 1 末起真实使用，反馈进 Backlog |

**基本原则：AI 负责"怎么实现"，人负责"做什么"和"算不算完"。** AI 不允许自行扩大需求范围（Feature Gate 拦着），人不干预具体实现细节（交给工程纪律管着）。

## 3. 模型分工与成本控制

按实测成本与效果分工（2026-09 实测：GLM 实际任务成本低于 DeepSeek）：

| 模型 | 占比 | 干什么 |
|---|---|---|
| **GLM 5.3 Flash（主力）** | 80~90% | 功能开发、UI、bug 修复、重构、测试编写 |
| **Kimi K3（专家）** | 5~10% | 数据宪法、架构决策、复杂调试、多模块耦合问题、代码评审 |
| **DeepSeek（备用）** | 0~10% | 仅当 GLM 在某类任务上明显不行时启用；生产环境 RAG 主模型（PRD Phase 3b）不变 |

**成本纪律**：不看 API 单价，看 **Cost / Successful Task**（含 agent 循环、重试、上下文重复注入）。每周记录一次：任务类型 × 模型 × 成功率 × 实际消耗。分工比例每月按实测调整，不为"架构好看"强行分流。

## 4. 工程纪律（十条军规，违反任何一条都算事故）

继承 AGENTS.md 铁律 + PRD §14，汇总如下：

1. 永不 `git push origin`，只用 `git push backup main`
2. 不加 `app.disableHardwareAcceleration()`
3. `enqueueSalesTask` 只加最外层入口
4. 消息读取只走 chatService；AI 调用只走 aiApiClient
5. WCDB 时间戳是秒，JS 是毫秒
6. 提交前必过 `npx tsc --noEmit` 零错误 + 对应模块回归测试全绿
7. **每完成一个任务立即 commit**，一次 commit 只干一件事
8. SSOT：一个业务事实只有一个写入源，新字段先查数据宪法
9. AI 无 publish 权：高风险操作（改阶段/移交/发布/对外）必须人工确认
10. **验收前不许宣布完成**：跑过验证、看过结果、DoD 逐条打勾，才算完

新增流程纪律：

11. **Feature Gate 七问**：任何不在当前 Phase 清单里的新需求，先答七问（属哪个 Phase？为什么现在必须做？会不会引入未来架构？会不会改变数据宪法？会不会新增事实源？会不会新增权限边界？挤掉什么？），答不过进 Backlog
12. **不顺手做未来 Phase**：技术上已具备依赖 ≠ 可以做。Phase 1 不做 Sync、不做多人、不做企业知识库

## 5. 标准任务工作流（每个任务七步）

每个开发任务（无论大小）走同一条流水线：

```
① 任务卡 → ② 计划 → ③ 实现 → ④ 自验 → ⑤ 提交 → ⑥ 验收 → ⑦ 文档回写
```

| 步骤 | 内容 | 负责 |
|---|---|---|
| ① 任务卡 | 一句话目标 + 对应 PRD 需求项编号 + DoD 条目。下达时显式声明纪律（如"先出计划给我审"、"TDD"） | 产品负责人 |
| ② 计划 | 改哪些文件、动哪些表、影响哪些现有功能、测试怎么写。**超过 3 个文件或动数据模型的任务，计划必须先审** | Agent 写，人审 |
| ③ 实现 | 按计划执行；偏离计划 >20% 时停下来重新对齐 | Agent |
| ④ 自验 | tsc + 回归测试 + 新功能实测（真实库跑一遍，不是"代码看着对"） | Agent |
| ⑤ 提交 | commit message 格式：`<scope>: <一句话>` + 关联需求项编号 | Agent |
| ⑥ 验收 | 对照 DoD 逐条确认；不通过打回 ③ | 产品负责人 |
| ⑦ 文档回写 | AGENTS.md 进度区 + HANDOVER.md 更新（当天完成，不欠账） | Agent |

**长任务记忆**：超过一天的Task，用 Planning with Files 模式——任务计划落在 `docs/tasks/<任务名>.plan.md`，每轮更新进度勾选，会话断了新会话读文件接着干。

## 9. 每日运作节奏

| 时间 | 动作 |
|---|---|
| 开始干活前 | 读 AGENTS.md 进度区 → 确认今日任务卡 → 向 agent 下达（含纪律声明） |
| 过程中 | agent 自治；偏离计划或碰到数据宪法冲突 → 停下来问，不猜 |
| 收工前 | 验收当日 commit → AGENTS.md/HANDOVER 回写 → 记录模型成本 |

**每周五**：对照本周任务卡自查 DoD 进度；跑一遍全系回归测试；模型成本周记（Cost/Successful Task）。

## 10. 暂停与升级规则

出现以下情况，**停止开发，先对齐再继续**：

1. 要加的字段/表不在数据宪法里 → 停，走宪法修订（评审），不直接建
2. 指标异常 → 按顺序排查：数据异常 → 埋点问题 → 口径问题 → 真实业务问题 → 才动代码
3. 任务连续 2 次验收不通过 → 换模型（GLM ↔ Kimi）或缩小任务粒度重做计划
4. 发现现有代码与 PRD 假设不符（如某"已有能力"实际不可用） → 记录进 HANDOVER，调整计划，不绕过
5. 任何"顺便把未来 Phase 做了"的冲动 → Feature Gate 七问，答不过进 Backlog
