## 1. 概述

### 1.1 背景

叉车销售客户来源两路：微信会话导入（WeFlow 既有管道）+ 网络渠道留资（抖音/视频号/小红书私信留手机号/微信号）。后者目前**没有统一入口**：联系方式（手机号/微信号）散在私信/评论区/表格里，容易漏跟、重复跟进、无记录。

### 1.2 目标

**确保每一个网络联系方式都能被可靠地导入、去重、在 SLA 内首触、留下完整流水，并且无损地转进现有 account。**

### 1.3 非目标（第一版不做）

线索分配/公海/回收/评分、平台 API 自动抓取、报价状态、商机状态。第一版不碰"分配/公海/回收"，避免把单机版做成半成品团队 CRM。

---

## 2. 核心概念：首触 SLA

**首触 SLA = 线索进来后，必须在规定时间内完成第一次联系**（电话/微信/短信任一）。

```
线索录入（导入时）
   │  created_at = now
   │  first_contact_deadline = created_at + crmLeadSlaHours   ← 导入时锁定落库
   ▼
超时未首触（status 仍为 NEW）→ 自动进「今日行动」高优先级提醒
```

| 决策 | 取值 | 理由 |
|---|---|---|
| 默认时长 | **24h**，可配 1~72h（`crmLeadSlaHours`） | 网络留资黄金窗口 24~48h；单机一人处理，24h 不凉线也不跟不过来 |
| 截止计算 | `first_contact_deadline` **导入时锁定落库**，不实时推导 | 改配置只影响新线索；历史线索截止不漂移（8/18 设 24h、8/20 改 8h 不应改掉已导入线索的截止） |
| 起算点 | 导入时间 `created_at` | 单机无分配环节；团队版才用 `assigned_at` |
| 提醒范围 | **只盯 `status='NEW'`** | NEW=从未首触过；标过 CONTACTED 即彻底退出 SLA，跟进交行动引擎 / R7 报价跟进，不重复报警 |
| 超时语义 | 仅提升提醒优先级，线索状态不变 | 超时 ≠ 失效 |

## 3. 数据模型（Schema）

3 张新表，建在 **`weflow-crm.db`**（与 account/quote_signal 同库）。全部加进 `crmDbService` 的 `ENTITIES` 白名单（`lead` 已预留）。

### 3.1 lead（线索主表）

```sql
CREATE TABLE IF NOT EXISTS lead (
  id INTEGER PRIMARY KEY AUTOINCREMENT,

  contact_type TEXT NOT NULL DEFAULT 'phone', -- phone(手机号)/wechat(微信号)/both(都有)
  contact_normalized TEXT NOT NULL,           -- 主联系方式归一化（both 时=手机号）
  contact_raw TEXT,                           -- 主联系方式原文（保留展示）
  wechat TEXT DEFAULT '',                     -- 微信号（contact_type=both 时并存）

  source TEXT DEFAULT '抖音',                 -- 抖音/视频号/小红书/自定义
  name TEXT DEFAULT '',                       -- 留资姓名/备注（可选）
  tag TEXT DEFAULT '',                        -- 标签（如：求 2T 车型）
  note TEXT DEFAULT '',                       -- 跟进备注

  status TEXT DEFAULT 'NEW',                  -- NEW→CONTACTED→(WX_ADDED)→ACCOUNT→DEAD
  dead_reason TEXT DEFAULT '',                -- 死因：号码无效/重复留资/明确不要/同行/非目标/已购车/联系不上/其他
  first_contact_channel TEXT DEFAULT '',      -- 首触渠道：PHONE/WECHAT/SMS（数据保留，第一版不展示统计）
  account_id INTEGER,                         -- 已转客户时关联的 account.id
  first_contacted_at INTEGER,                 -- 首次联系时间戳
  first_contact_deadline INTEGER NOT NULL,    -- 首触截止（导入时锁定 = created_at + SLA）

  created_at INTEGER NOT NULL,
  updated_at INTEGER,

  -- team-routing-reserved：单机业务绝不依赖，恒为 0/NULL；本机用户即默认 owner
  owner_id INTEGER DEFAULT 0,
  pool_id INTEGER DEFAULT 0,
  assigned_at INTEGER,
  private_deadline INTEGER
);

CREATE UNIQUE INDEX IF NOT EXISTS idx_lead_contact ON lead(contact_type, contact_normalized);
CREATE INDEX IF NOT EXISTS idx_lead_status ON lead(status);
CREATE INDEX IF NOT EXISTS idx_lead_source ON lead(source);
CREATE INDEX IF NOT EXISTS idx_lead_sla ON lead(status, first_contact_deadline);
```

- 唯一索引 `(contact_type, contact_normalized)` 是去重的**硬保证**（库里兜底，手机号/微信号两类互不碰撞）；应用层只做友好统计。
- `idx_lead_sla` 服务 SLA 扫描（`WHERE status='NEW' AND first_contact_deadline < now`）。

### 3.2 lead_activity（线索流水，只增不改）

```sql
CREATE TABLE IF NOT EXISTS lead_activity (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  lead_id INTEGER NOT NULL,
  action TEXT NOT NULL,        -- IMPORTED/CONTACTED/WX_ADDED/QUOTED/TO_ACCOUNT/DEAD/REOPEN/EDITED
  note TEXT DEFAULT '',
  created_at INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_lead_activity_lead ON lead_activity(lead_id);
```

- `REOPEN` 是 **action** 不是状态（DEAD → REOPEN → NEW）。
- `QUOTED` 走 **activity** 不走状态（状态机保持轻量，见 §5）。
- 首触渠道记录在 lead 表 `first_contact_channel`，支撑后续"电话/微信/短信首触成功率"分析。

### 3.3 import_batch（导入批次统计）

```sql
CREATE TABLE IF NOT EXISTS import_batch (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  source TEXT NOT NULL,               -- 本次导入来源
  file_name TEXT DEFAULT '',          -- 原文件名（文本粘贴='粘贴文本'）
  total INTEGER DEFAULT 0,            -- 文件总行数
  valid INTEGER DEFAULT 0,            -- 有效导入数
  duplicate INTEGER DEFAULT 0,        -- 去重跳过数
  invalid INTEGER DEFAULT 0,          -- 无效号码数
  created_at INTEGER NOT NULL
);
```

只存统计，不存失败行明细。导入完成时前端在**当前弹窗内**展示「有效 X / 重复 Y / 无效 Z」+ 无效行列表，关掉即丢。

## 4. 功能设计

### 4.1 批量导入（Excel/CSV + 文本粘贴，统一进清洗层）

**两种入口**，都进 `crmLeadImportCore`：

- **A. Excel/CSV**：主流程。每行一条线索（手机号/微信号，可含姓名/标签/备注/来源列）。
- **B. 文本粘贴**：轻量入口。私信原文/手机号清单直接粘贴到 textarea → 每行跑同一套清洗 → 预览 → 确认导入。匹配"复制私信 → 粘贴"的真实场景，不要求先整理 Excel。

**清洗规则**（纯函数，`crmLeadImportCore.ts`，可单测）：

| 规则 | 处理 |
|---|---|
| 手机号提取 | `1[3-9]\d{9}`（大陆手机号）；兼容 `+86`、空格、`-`、括号 |
| 微信号提取 | 带标注 `微信/VX/vx/威信[:：]` 后跟的号，或 `[A-Za-z][A-Za-z0-9_-]{5,19}`（字母开头 6~20 位）；去前导 `@` |
| 主联系方式 | **手机号优先**：同行既有手机号又有微信号 → `both`（手机号为主，微信号入 `wechat`）；只有微信号 → `wechat` |
| 规范化 | 手机号去空格/横杠/括号/86 前缀（函数命名 `normalizeCnMobile`，明确业务=大陆手机号）；微信号去空格转小写 |
| 无效过滤 | 手机号、微信号都提取不到 → `invalid` 计数，跳过 |
| 同批去重 | 同 `(contact_type, 归一化)` 只取首行 |
| 跨批去重 | **不预查 exists 再插**：直接 `INSERT`，唯一索引冲突捕获为 `duplicate` 计数（数据库唯一索引负责最终正确性，应用层只负责友好统计） |
| 姓名/标签 | Excel 有对应列则带出，否则留空 |

**导入事务**：导入只写 crmDb（lead + import_batch + lead_activity），**单库事务**（BEGIN/INSERT/COMMIT）。导入后立即调 `scanLeadSla()`。

### 4.2 线索池页面（LeadPage）

- **列表**：联系方式（手机号/微信号，带类型徽章）/ 来源徽章 / 姓名标签 / 状态 / 录入时间 / SLA 截止（超时红色「已超时 N 天」，剩余绿色「剩 N 小时」）
- **筛选**：来源（全部/抖音/视频号/小红书/自定义）、状态、只看超时
- **搜索**：联系方式 / 姓名 / 标签
- **操作**（选中行）：
  - 「已首触」→ status CONTACTED + `first_contacted_at` + 选渠道（电话/微信/短信，写入 `first_contact_channel`）+ 流水
  - 「已加微」→ status WX_ADDED + 流水
  - 「转客户」→ 见 §4.4
  - 「无效」→ status DEAD + **必填死因**（预设：号码无效/重复留资/明确不要/同行/非目标客户/已购车/联系不上/其他）→ 流水
  - 「恢复」→ DEAD 可 REOPEN 回 NEW + 流水
- **详情**：点行进抽屉，活动时间线（lead_activity 倒序）+ 编辑备注

### 4.3 首触 SLA 提醒 + 完成闭环（复用今日行动引擎）

**`scanLeadSla()`**（函数化，不写死"08:00 逻辑"；两个调用点：导入完成后 + 每日 08:00；后续可加启动扫描/手动刷新）：

```
SELECT id, contact_normalized, source, first_contact_deadline
FROM lead
WHERE status = 'NEW' AND first_contact_deadline < now
  AND 不存在 pending 的 sla_lead 卡（幂等）
```

命中 → 插入 `follow_up_task`（salesDb）：

```ts
{
  display_name: '📥 抖音线索 138****',      // 来源 + 脱敏联系方式
  title: `线索 ${contact_normalized 脱敏} 已超 ${超时时长} 未首触`,
  trigger_type: 'sla_lead',
  source_id: lead.id,                       // 幂等键
  priority_score: 按超时时长递增,
  due_at: now
}
```

**幂等双保险**：
- 应用层：建卡前查 `follow_up_task WHERE trigger_type='sla_lead' AND source_id=? AND status='pending'`
- 数据库层：`follow_up_task` 在 salesDb 建 **partial unique index** 兜底：

```sql
CREATE UNIQUE INDEX IF NOT EXISTS idx_ft_sla_once
ON follow_up_task(trigger_type, source_id)
WHERE status = 'pending';
```

**完成闭环 `completeLeadFirstContact(taskId)`**——把"卡片完成 + 线索首触"视为一个业务操作：

> **跨库约束**：`follow_up_task` 在 `weflow-sales.db`，`lead` 在 `weflow-crm.db`，两个独立 sql.js 连接，**无法用单个 BEGIN/COMMIT 包裹跨库写**。方案：
>
> 1. 先 **crmDb**：事务内 检查 lead 仍为 NEW → `status=CONTACTED` + `first_contacted_at=now` + 流水
> 2. 再 **salesDb**：`follow_up_task.status='done'`
> 3. **自愈**：若第 2 步失败，残留 pending 卡无害——下次 `scanLeadSla()` 发现 lead 已非 NEW 且存在 pending 卡 → 顺手标 DONE
>
> 顺序必须「先 crm 后 sales」：若反之 salesDb 先成功而 crmDb 失败，lead 仍 NEW，下次扫描会重建一张卡，幂等被破坏。

### 4.4 转客户（与现有 account 打通）

- 手机号线索 → `account.phone = 手机号`；微信号线索 → `account.custom_fields.wxid` + note 记「微信号线索」
- 转客户前查重（手机号查 `account.phone`、微信查 `custom_fields.wxid`）→ 已是客户则提示「已是客户 XX」，直接关联 `account_id`，不重复建
- 成功后 lead → ACCOUNT + 流水 `TO_ACCOUNT`，不再参与 SLA 提醒

## 5. 状态机与流水

**5 态，保持轻量**：

```
 导入（清洗后有效）
        ▼
   ┌─ NEW ──► CONTACTED ──► WX_ADDED ──► ACCOUNT（关联 account）──► 成交（走 CRM 既有管道）
   │  ▲          │
   │  │          └──► DEAD（无效/流失，必填死因）──►（REOPEN action）──► NEW
   │ REOPEN
   │
   └──（DEAD 也可从任意前置态直接发生）
```

| 状态 | 含义 | 参与 SLA 提醒 |
|---|---|---|
| NEW | 从未完成任何有效首触 | ✅ |
| CONTACTED | 首触已完成 | ❌ |
| WX_ADDED | 已完成加微 | ❌ |
| ACCOUNT | 已进入正式客户（关联 account） | ❌ |
| DEAD | 明确终止（必填死因） | ❌ |

- **QUOTED / FOLLOWED_UP / CALLBACK / NO_REPLY 等推进动作全部走 `lead_activity`**，不进状态机。线索完整故事由时间线呈现，主状态保持 5 态（避免 `CONTACTED_BUT_NOT_REPLIED` 式状态爆炸）。
- **REOPEN 是 action 不是状态**：流程为 `DEAD → REOPEN action → NEW`，Activity 记录 `DEAD` + `REOPEN`。

## 7. 集成点与跨库约束

| 现有能力 | 复用方式 |
|---|---|
| `ENTITIES` 白名单 | `lead` 已预留，新增 `lead_activity`/`import_batch` 两个实体 |
| `follow_up_task`（今日行动，salesDb） | SLA 提醒 = 新增 `trigger_type='sla_lead'`，复用列表/排序/完成回写 |
| `salesQueue.enqueueSalesTask` | 导入清洗/转客户等重操作全部走串行队列（防死锁铁律） |
| `account`（crmDb） | 转客户复用建客户逻辑 + phone/wxid 查重 |
| 配置系统 `configRef.get` | 新增 `crmLeadSlaHours` / `crmLeadSourcePreset` |
| R7 报价跟进每日 08:00 扫描 | `scanLeadSla()` 挂同一天扫描线 |

**跨库铁律**（本模块特有）：
- lead 系列表在 **crmDb**，follow_up_task 在 **salesDb**，两库独立 sql.js 连接。
- 单一业务操作尽量落在单库内（导入 = 全 crmDb，可事务）；必须跨库的（SLA 完成闭环）用「先 crmDb 后 salesDb + 扫描自愈」顺序，不追求假事务。
- 建表/索引分别在各自 Service 的 init 里执行，幂等（IF NOT EXISTS）。

## 9. 验收标准

1. 同一批表格导入两次 → 第二次全判「重复」，lead 表数量不变；手机号与微信号两类去重互不误伤
2. 文本粘贴私信原文（含微信+手机号混排）→ 正确提取、`both` 线索手机号为主微信号进 `wechat`、可预览后导入
3. 一行同时含微信+手机号 → `both`，去重按手机号
4. `first_contact_deadline` 导入时锁定：建 1 条线索后把 `crmLeadSlaHours` 改小 → 该历史线索截止时间**不变**
5. `scanLeadSla()` 对超时 NEW 线索建卡，重复扫描**不重复建卡**（应用层查询 + partial unique index 双兜底）
6. 点今日行动完成 SLA 卡 → `follow_up_task=done` + lead `CONTACTED` + `first_contacted_at` + 流水，三者一致；无脏卡
7. 「无效」必填死因 → DEAD + 流水；「恢复」REOPEN 回 NEW + 流水
8. 转客户：联系方式已是客户 → 提示并关联；不是 → 建 account 且 lead 变 ACCOUNT
9. `npx tsc --noEmit` 零错误 + 单测套件全绿（清洗/去重/SLA/闭环四组用例）

> ✅ **验收结果**（2026-08-19）：1-9 全部通过。`scripts/crm-lead-test.ts` 53/53；`tsc --noEmit` 零错误；vite build 通过；mock-electron IPC smoke 14/14（含统一信号流 `lead:` 分支完成/跳过闭环）。

- SLA 起算点从 `created_at` 切到 `assigned_at`；超时提醒改为回收公海 + 重新分配；lead 按 owner 隔离可见。
- 数据演进方向：`lead`（人/联系方式）与 `lead inquiry / opportunity`（一次商机）**分离**——同一联系方式跨平台/跨时间可能是不同商机。第一版接受「一联系方式一 lead」（目标=避免重复跟进），团队版拆分。
- 届时走 `docs/PRD-团队版-WeFlow+Twenty底座.md`，lead 映射为 Twenty 自定义对象。
