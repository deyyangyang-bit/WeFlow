## 四、打包环境问题（⚠️ 2026-08-13 已重新定位真因，本节诊断已修正）

> **原判断"dist 是 Node wrapper 混入的坏 Electron v24"是错的**。
> 真实根因：**`ELECTRON_RUN_AS_NODE=1` 环境变量**让 Electron 以 Node 模式启动——
> GUI 不出现、`--version` 输出**内嵌 Node 版本 v24.17.0** 而非 Electron 版本。
> `node_modules/electron/dist` 本身完好（Electron.app 共 276MB），**从未损坏**。

### 症状
- 终端直接跑 `Contents/MacOS/Electron --version` 输出 `v24.17.0`（正确应为 `v43.0.0`）
- `electron-builder` 打包成功（exit 0，dmg/zip 都产出），但 `.app` **启动即退出、零输出、无日志**

### 根因（已修正）
`ELECTRON_RUN_AS_NODE=1` 被注入 shell/CLI 会话（部分 Node 工具链会设置该变量，`echo $ELECTRON_RUN_AS_NODE` 可查）。
该变量令 Electron 二进制以 Node 模式运行：
```
$ echo $ELECTRON_RUN_AS_NODE          # 1
$ node_modules/electron/dist/Electron.app/Contents/MacOS/Electron --version   # v24.17.0（Node 版本）
$ unset ELECTRON_RUN_AS_NODE
$ node_modules/electron/dist/Electron.app/Contents/MacOS/Electron --version   # v43.0.0（正确）
```
判定依据：
- 同一二进制，`unset` 该变量后 `--version` 即变回 `v43.0.0`（2026-08-13 实测）
- `Electron.app` 目录 276MB，是完整 Electron 安装，非 33KB 假体
- `dist/version` = `43.0.0` 本来就是对的

### 修复（已落地，2026-08-13）
`vite.config.ts` 在 spawn Electron 前执行 `delete process.env.ELECTRON_RUN_AS_NODE`（dev/build 路径全防护）。
Linux 侧同款处理见 `electron/services/keyServiceLinux.ts:91`。
打包产物由 Finder/launchd 直接启动，不继承终端环境变量，不受此坑影响。

### 当时的无效操作（可忽略，勿再重复）
- ❌ 删除 `node_modules/electron/dist` 重建 —— **不必要**（dist 从未损坏），且会触发 110MB 下载
- ❌ 清空 `~/Library/Caches/electron/` —— 与根因无关
