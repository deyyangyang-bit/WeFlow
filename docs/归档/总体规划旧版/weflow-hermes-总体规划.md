## 三、迭代二 · Hermes 与知识治理（约 3~4 周）

### Hermes 三段式架构
- 触发层（何时做）
  - 事件触发：新消息增量（订阅现有机制）
  - 定时触发：挂入行动引擎每日 08:00 扫描
  - 人工触发：页面提问 / 一键处理
- 工具层（能做什么）
  - 读：查客户 / 查聊天（走 chatService）/ 查知识 / 查阶段历史
  - 写：建待办 / 打标签 / 提知识提案 / 生成草稿
- 判断层（理解与表达）
  - LLM 走 aiApiClient，只做理解 + 生成
- 人（落锤）
  - 高风险操作确认队列

### 权限三级分级
- 🟢 只读：自由调用
- 🟡 低风险写：可自动执行 + 全量审计日志
- 🔴 高风险写（改阶段 / 移交 / 发布知识 / 对外发送）：必须人工确认

### 知识治理升级
- 治理字段：status（状态）/ authority（权威等级）/ version（版本链）/ TTL（保质期）
- published（已发布）过滤 + 审核 Tab
- 反哺回路：聊天发现 → proposal（提案）→ 人审 → 发布
- AI 无 publish 权限（账号级硬约束）
- 效果回流：使用埋点 × 阶段结果归因（哪条话术在赚钱）
- TTL 主动巡检（到期问负责人"还成立吗"）

## 六、多用户 · 权限 · 数据隔离（NAS 企业层）

### 分层架构
- 个人层：每台销售电脑独立 WeFlow，物理隔离，互不可见
- 企业层：NAS（WeKnora + 治理库 + 备份仓库 + 汇聚数据）

### 单向上行规则（什么数据允许进 NAS）
- ✅ 上行：已审核知识 / 成交登记 / 报价版本 / 加密备份 / 审计记录
- ❌ 不上行：原始聊天记录（默认）/ 未审核草稿与 proposal
- 原则：NAS 汇聚"知识"与"事实记录"，不汇聚"聊天原始流水"

### 权限矩阵（RBAC 四角色）
- 销售：本人客户全部 / 读 published 知识 / 不可见成本价 / 可提 proposal
- 销售主管：团队只读（阶段与成交，不看聊天原文）/ 审核发布 / 移交 / 可见成本
- 管理员：归属管理 / 账号角色 / 密钥 / 全部知识库
- 落地：WeKnora workspace 隔离 + 四角色；敏感知识单独建库 + 网关层条目级 ACL

### 数据隔离机制
- 知识库隔离：published 按角色分库 / ACL 标签
- 撞单仲裁：上行成交登记按手机号去重，同人跟进触发主管仲裁
- 离职交接升级：移交记录上行留痕，新设备恢复归属，证据链不断
- 备份即上行原型：迭代一的备份通道 = 未来同步通道的基础

## 七、新需求 · 客户资源分配与 AI 初判归档

### 功能一：客户资源分配（迭代一 · 纯本地）
- 录入：分配人员角色（主管/销售助理）批量导入 Excel / 粘贴清单
- 查重：对已有客户手机号自动去重
- 分配引擎三模式：比例权重（可调，默认）/ 轮询 / 按负载均衡
- 生命周期：待分配池 → 已分配 → 认领（接首触 SLA 24h）→ 超时回收再分配
- 加好友兜底：分配后 24h 未加好友 → 提醒销售，每 24h 复查，第 3 次提醒抄送主管 → 3 次后自动回收再分配
  - 检测方式：手机号匹配本地联系人库，客户主动添加也算
  - 再分配优先给其他人，防止同一销售循环占位
  - 回收原因留痕，记入该销售分配档案
- 数据基础：lead 表 owner_id / pool_id / assigned_at 预留字段启用
- 审计留痕：录入人 / 分配对象 / 认领时间 / 回收记录

### 功能二：认领 24h 后 AI 首次分类（迭代二起）
- 触发：认领满 24h 挂入每日扫描 + 手动立即初判按钮
- AI 输出：阶段初判 / 客户类型（经销商/终端）/ 意向评分 / 画像 12 字段（带证据链）
- 人可修正：销售可改，改动留痕（AI 提议、人落锤）
- 上行 NAS 存档：结构化档案 JSON，聊天原文不上行
- 权限：条目级 ACL——归属销售本人 + 主管/管理员可见

### 架构影响
- NAS 新增"客户档案库"（Postgres），集中式 CRM 的胚胎
- NAS Postgres + 加密上行通道提前到迭代三（复用迭代一备份通道）
- 顺序：迭代一分配+备份 → 迭代二 AI 初判落本地 → 迭代三档案上行 NAS

## 八、核心原则

- 规则负责「什么时候该行动」
- Hermes 负责「行动时带什么知识」
- 效果回流负责「下次行动更聪明」
- 知识是服务，不是文件
- 先审后发（Review-before-Publish）
- AI 可提议一切，落锤权在人
- 底座可替换，治理逻辑是自己的资产
- 护城河 = 微信聊天数据 × 业务结果的配对
