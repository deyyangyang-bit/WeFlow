## 3. 档位映射表

### 3.1 自动化程度（P0）

| 档位 | 直接写入阈值<br>`crmEnrichAutoApply` | 待确认下限<br>`crmEnrichThreshold` | 置信阈值<br>`crmAutoConfirmThreshold` | 一句话后果（UI 文案） |
|------|------|------|------|------|
| 保守 | 0.90 | 0.80 | 0.85 | 大部分信息只做建议，基本都要你确认后才写入 |
| **标准（推荐）** | **0.85** | **0.70** | **0.80** | 高置信直接写入档案，中置信进跟单中心待你打勾 |
| 积极 | 0.75 | 0.60 | 0.70 | 系统尽量自己处理，只有拿不准的才来打扰你 |

- **标准档 = 落库默认值**：`0.85 / 0.70 / 0.80`，与 `useState` 初值逐字一致（`crmEnrichAutoApply` / `crmEnrichThreshold` / `crmAutoConfirmThreshold`）。
- 三档均满足不变量 **待确认下限 ≤ 直接写入阈值**，且三个值都落在滑杆量程 `[0.5, 1]` 的 `0.05` 栅格上。
- 反推：`tierOf()` 逐字比对三个值，命中不了任一档即返回 `''`（**未选择态**）——手调过的值（如 `0.87/0.70/0.80`）不会被假装归入某一档。
- 映射常量全部带注释说明来源（现状默认值），写在 `src/utils/settingsTiers.ts:39-49`。

## 5. 遗留项

1. **微博 UID 列无法折叠**（部分完成）：任务单要求「微博『数字 UID』『Cookie JSON 数组』标记实验性并折叠」。Cookie 弹窗（`:7001` 微博 Cookie（实验性））与配置入口（`:4596` 折叠）已达标；但**「数字 UID」是白名单/黑名单表格的一列**（`:4940` 社交平台（微博 · 实验）），逐行内嵌在 `filteredSessions.map` 里——折叠一个表格列需要重构表格栅格，超出「纯展示层、不全量重排」的安全边界。**已做的替代**：表头、输入 placeholder、空态回显三处都加了「实验」字样。**未做**：列的折叠。
2. **`AdvancedFold` 内容未重新缩进**：API 服务 tab 的正文（约 330 行）与四处提示词、故障自检折叠的正文保持原有缩进层级，未做纯空白重排——避免制造 300+ 行无信息量的 diff 噪声。**已知代价**：这几处的 JSX 缩进比实际嵌套浅一级。
3. **备份状态词典与 `shared/auditDict.ts` 的 `BACKUP_LAYER` 是两份**：同词汇、两种渲染语境（审计流水嵌在整句里用「完成」；设置页是状态摘要用「✓ 完成」）。`shared/` 不能反向依赖 `src/`，故未强行合并。**改词时需两处一起看**，已在 `src/utils/backupStatusLabel.ts:8-11` 与 `shared/auditDict.ts` 双向注释。
4. **`settings-nav-test` 未新增设置页控件级断言**：本刀的控件级护栏全部落在新的 `scripts/settings-tiers-test.ts` 里。若后续想合并成一套，需先确认 §11 的计数口径。
5. **Max Tokens 档位标签不含数字**：按任务单「数字收高级」执行，界面上「短/标准/长」不带 token 数；用户要精确值需展开「高级 · 自定义长度」。若实测中发现一线销售搞不清档位差异，可考虑在标签下补一句「约 X 字」。
