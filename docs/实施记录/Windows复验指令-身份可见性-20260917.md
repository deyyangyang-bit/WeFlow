## 1. 升级前准备（顺序执行，逐项留证）

1. **记录本地销售角色与署名**：设置页截屏「身份档案」姓名与角色（角色应为销售）；命令行留证：
   `userData/WeFlow-config.json` 中的 `identityName`、`identityRole` 原值（只读复制，不改）。
   **全程保持原署名，不改姓名。**
2. **记录现有中央绑定状态**：设置页截屏中央同步状态（绑定的工作区/员工/设备、最近同步时间），
   确认当前处于「已绑定」。**安装修复构建后这组绑定必须原样保留——这是「不被错误覆盖」的硬检查**。
3. **正常退出应用**（托盘退出，不杀进程），备份 `userData` 整目录
   （默认 `%APPDATA%/weflow` 或安装版实际路径，含 crm/sales 两库与配置）。
4. 记录现装版本号（关于页或 `latest.yml` 对照）。

## 2. 安装修复构建

1. 双击 `WeFlow-1.0.1-Setup.exe` 覆盖安装（不卸载，保留 userData）。
2. 启动后**逐项确认**：
   - 应用锁/身份档案与第 1 步记录一致（未被重置）；
   - 中央同步状态仍为「已绑定」，`deviceId`/员工编号与第 2 步记录一致——**绑定被清空或
     变更 = 验收失败**，立即停止并回退（见 §4）；
   - 无额外配置/数据变更提示被误点（升级不做数据迁移，出现要求改库的提示即异常）。

## 3. 用现有 acceptance 合成线索复验（不重新分配真实线索）

沿用此前验收已建立的合成线索机制（上行→中央→合成 assign 下行，中央 seq 930 那批的同一流程）：

3.1 **自己的分配可见**：
   - 中央（或在管理机）对**本机绑定的中央销售身份**做一条新的合成 assign 下行（mode=manual）；
   - 本机等待同步轮（设置页中央同步「最近下行」推进 / 或手动「立即同步」）；
   - 打开「线索」页（销售视角 = 我的资源卡形态）：**该合成线索必须出现在「我的」列表**
     （署名与中央显示名不同也必须可见——这正是本轮修复点）；「我的」chip 计数包含它；
   - 点认领：必须成功（归属别名算本人），认领后仍可见且进入「跟进中」。

3.2 **他人的分配不可见**：
   - 对**其他销售员工**的中央身份做一条合成 assign 下行（目标 = 那位销售的 employeeId）；
   - 本机同步后：**不得出现该线索**；且自己的列表条数不因此增加（目标防护：pull 路由按
     targetEmployeeId）。

3.3 **回归检查（顺带）**：
   - 解绑 → 别名消失：中央名分配对销售视角隐藏，本地署名分配照常可见，界面仍是销售视角
     （不是变成看全部）；重新绑定后恢复可见；
   - mode：3.1 的落地行在审计（线索页「分配审计」）里 `mode=manual`、SLA 截止时间与中央
     下行值毫秒一致（可在审计 detail 中核对 `sla1Deadline` 原值）。
