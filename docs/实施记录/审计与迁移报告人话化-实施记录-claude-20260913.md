### 2.1 覆盖护栏（`scripts/audit-dict-test.ts`）

`collectActions` 静态扫描 `electron/**/*.ts`（排除 `.d.ts`）的**四种写入形态**，断言「源码里出现的每个 action 都在词典里」：

| # | 形态 | 取字面量位置 |
|---|------|------|
| ① | `auditAppend(actor, 'action', …)` | 第 2 个实参 |
| ② | `INSERT INTO audit_event … VALUES (…)` | 紧随的 `[…]` 数组第 2 个元素 |
| ③ | `create('audit_event', { action: '…' })` | `action:` 的字面量 |
| ④ | `writeAudit('action', …)` 调用点 | 第 1 个实参（**跳过 `function writeAudit(` 定义本身**） |

**形态 ④ 是本刀新增的补漏**：`crmDeliveryService.writeAudit()` 是包装函数，前三种形态都扫不到它，导致 4 条 action 长期无翻译（见 §2.2）。模板串拼接的 action 无法静态枚举，护栏将其列为 **dynamic 写点报告**要求人工登记——这正是 `trade_in_proposal_*` 两条被发现的路径。

**未覆盖时的行为（设计稿 §04「不留白、不静默」）**：`resolveAuditAction()` 回落到 `{ label: 原始 key, untranslated: true, describe: genericParts }`，UI 渲染原始 key + 灰色**「未翻译」**标签，绝不显示空白或编造文案。

### 2.2 护栏扫出的真实缺口（本刀一并修复）

首轮护栏报告出 4 条**从未被翻译**的 action，全部由 `crmDeliveryService.writeAudit()` 写入：`diff_task_autoclose`、`warranty_reminder_autoclose`、`trade_in_proposal_accept`、`trade_in_proposal_reject`。已补词典条目。
