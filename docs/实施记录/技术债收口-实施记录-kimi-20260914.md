## 1. 迁移失败项人工闭环

### 数据核实结论（真实库只读探针，探针脚本用后已删）

模块②（account → customer 归并）真实库 21 条失败全部为「无可用身份锚点」：
**无 11 位手机号、无 session_id，且逐一按名称比对后 0 条存在同名 customer**——
没有可归并的对象，唯一正确的闭环是人工「确认忽略」。其中 `张家港保税区双澄贸易有限公司` 有 2 条重复 account。

### 设计决策

- **存储选 crmDb 新表**而非 config/scan_state：与报告同库、可审计、可被内网同步携带；`scan_state` 是数值型游标表，塞 JSON 是扭曲。
- **手动归并未做**：21 条经实测全部无同名 customer 可归，「按名称归并」入口暂无对象；若后续出现可归项再开（设计已在宪法留好边界）。

## 2. tsc 门禁覆盖 electron/

### ②A 棘轮门禁（治本：先让错误"只降不涨"）

- 新增 `scripts/typecheck-node-ratchet.cjs`：跑 `tsc -p tsconfig.node.json`，错误数 > BASELINE 即 exit 1，低于基线提示收紧。
- `package.json`：`typecheck` 改为 `tsc --noEmit && node scripts/typecheck-node-ratchet.cjs`；新增 `typecheck:node`。
- HANDOVER §11 同步（棘轮口径 + 新命令 + 新测试）。

### ②B 存量消肿：156 → 7

分类与修法（全部机械、零行为变化；详见子任务交付）：大头是 `ExportContext.ts` 拆分时漏 import（55）、`ExportStatsService` 重构遗留的委托错位（11）、`bizService` 蛇形字段收窄（16）、formatters `unknown` 簇（17）、`config.ts` 补齐 schema 缺失键（默认值与消费端回退完全一致）等 21 个文件。

### 剩余 7 个错误（登记不修）

- `crmDbService.ts:1230`（TS2558 多余类型实参）、`:1537`（对象字面量多 `linked` 字段）
- `crmIpcHandlers.ts:436`（`FirstClassifyRunResult` 用在 Promise 位置，疑似漏 await）、`:518/:521`（`() => void` 传给 `() => Promise<unknown>`）
- `export/index.ts:63`（facade 委托到不存在的方法，全仓无调用方，删 API 或补实现需决策）

### ⚠️ 疑似真 bug（消肿中照出，未顺手修，待拍板）

1. **`crmIpcHandlers.ts:176`**：`CrmRow` 直接传给期望 `{count, quantity, amount}` 的参数——**商机统计可能恒 0**，需核实运行时数据。
2. **`crmIpcHandlers.ts:436`**：首次分类结果疑似漏 await。
3. `messagePushService.ts:1171/1174`：`session.type` 数值与字符串比较永不成立，「私聊跳过」分支可能是死路（类型错误已修，死分支本身未动）。
