> | **curl 参数冲突（本轮）** | 首次真实切换暴露：探测的 curl `-w` 参数含**真实换行符**，被本脚本族自己的参数构造规则（拒绝 CR/LF）拒绝，端点验收在装有 curl 的 Windows 上必然抛异常。改为「字面量反斜杠 + n」两个字符（curl 自己解释为输出换行），CR/LF 安全拒绝规则保留不放宽；状态标记改为**只从 stdout 末尾**提取，响应正文中的相同文本不再干扰解析。隔离测试新增「真实参数构造组合测试」（mock 下沉到进程执行叶子，参数构造不 mock）与真实外部命令包装层的无害子进程回显用例，格式参数改回真实 LF 时对应测试必然失败 |
> | **回退加固（本轮）** | 首次真实切换暴露：失败处理在回退**之前**读取 `native-caddy.stderr.log`，文件正被刚启动的原生进程占用时 IOException 逃逸出 catch 块，**自动回退整体没有执行**。现改为：回退优先（进程回收与容器恢复各自捕获失败、互不跳过），stderr 日志等非关键诊断放回退之后且包在独立防御 try/catch 里（失败只记录警告，不影响回退结论与退出码）；隔离测试新增日志被占用 / 存在性检查抛异常 / 回退本身失败三类真实脚本用例，并保留「退回旧诊断流程」的变异负例 |

> **注意：本脚本族不是「只读」工具**——`Install-NativeCaddy.ps1` 会在 F 盘部署根下创建目录、从官方归档展开 `caddy.exe`、渲染并写入生效配置、收紧并核验 ACL；`Start/Stop-NativeCaddy.ps1` 会停止/启动容器 caddy 与原生进程。真正只读的是 `Test-DeploymentContract.ps1`（写 `-SkipRuntimeChecks` 时）与诊断脚本。

本文件是 Windows 测试机上的**第一阶段受控验收**操作说明。它只覆盖把 TLS 终结从容器换成宿主
原生进程，**不修改 Central / PostgreSQL、不改数据库、不删卷、不注册长期服务**。

## 1. 为什么需要原生方案

容器 Caddy 方案的 TLS 链与主机名验证已经成功，但 `/health`、`/ready` 返回 403：

- 主机自测时，容器内 Caddy 看到的来源是 Docker 网桥网关 `172.18.0.1`，不是真实的 LAN 客户端地址；
- `central/Caddyfile` 的 `remote_ip` 按「直接连接对端」判定来源，因此把来自 LAN 的请求也判为不允许网段；
- 这是设计上的 fail closed，不是配置错误。

要让判定恢复真实，必须在**宿主网络栈内**终结 TLS，让 socket 的对端就是 LAN 客户端本身。原生
Caddy 正是这一点；安全策略（只允许 `192.168.1.0/24`、其余 403、不信任 `X-Forwarded-For`）完全不变。

**尚未确认**：第二台 LAN 客户端（`192.168.1.53`）在经过 Docker 转发时被呈现成哪个 peer，仍需在
Windows 切换前配合采样一次。不要在没有该证据的情况下断言「容器方案必然不可用」。

## 2. 目标链路

```
LAN 客户端
  → Windows 宿主原生 Caddy，192.168.1.57:443
  → http://127.0.0.1:8787
  → Central / PostgreSQL
```

端口纪律：只开放 443。**不开放** 80、8787、5432、2019。PostgreSQL 继续不映射宿主端口。


## 5. 操作顺序

以下命令在**解压后的交付包根目录**执行。

### 5.1 本机准备（会写 F 盘目录/展开 exe/渲染配置）+ 官方 validate

```powershell
powershell -ExecutionPolicy Bypass -File .\central\windows-caddy\scripts\Install-NativeCaddy.ps1 `
  -PackageRoot $PWD -NativeEnvPath .\native.env
```

它会报告：计算机名与当前 IPv4（含 DHCP 提示）、Central 回环健康与契约、443 占用者、程序目录冲突；
随后**先核对官方归档 SHA-256**，再展开 `caddy.exe`（既有 exe 必须通过同一摘要核验才复用），
创建 F 盘目录、**收紧并核验 PKI/状态目录 ACL**，渲染配置并让官方 `caddy validate` 校验；
**校验不通过、ACL 失败、Central 不健康或绑定地址不属于本机都不会写入生效配置。**
既有生效配置与本次渲染不同时默认拒绝覆盖（需显式 `-Force`）。

### 5.2 显式授权后切换

```powershell
powershell -ExecutionPolicy Bypass -File .\central\windows-caddy\scripts\Start-NativeCaddy.ps1 `
  -PackageRoot $PWD -ReleaseDir <现有 Central 发布目录> -NativeEnvPath .\native.env -Authorized
```

不带 `-Authorized` 时脚本只打印计划并以退出码 2 空跑，不做任何变更。带 `-Authorized` 时它按顺序：

1. 记录切换前的容器状态到 `F:\WeFlow-Test\state\native-caddy.state.json`（供回退核对）；
2. **只停止容器 caddy**，统一使用
   `docker compose -p weflow-test --env-file central/proxy.env -f docker-compose.central.yml -f docker-compose.central.tls.yml stop caddy`；
   不 `down`、不删容器、不删卷、不动 Central/PostgreSQL；
3. 启动原生进程后**立即在内存里保存本轮进程身份**（PID + 可执行路径 + 实际启动时间），
   再把它写到 `state\native-caddy.current.json`。记账只是**磁盘侧记录**：
   即使写盘失败，失败回退仍能凭内存身份精确结束本轮进程；
4. 端点验收：在完整 TLS 校验下请求 `/health` **与** `/ready`，两者都必须 HTTP 200 且响应契约成立
   （`ok` 布尔为真、`service=weflow-central`、`protocolVersion` 为 JSON 整数且等于 1、
   `database=ready`）。**403（来源门禁拒绝）不算通过**，一律触发回退；
5. 任一步失败即进入回退：结束本轮原生进程（结束前核对身份、结束后确认进程确实消失），
   并**只**在「本轮确实停过且原先在运行」时 `start caddy`；
   回退的每一步都有结构化结果，结论只用布尔值判定，不靠搜索日志文本；
   回退会在 `state\native-caddy.rollback.json` 留下诊断记录。

### 5.3 导出公开根证书并做 TLS 验收

原生首次启动会生成**全新的独立测试 CA**。它与旧容器 CA 不同是**预期行为**，不是故障。

```powershell
Copy-Item F:\WeFlow-Test\pki\pki\authorities\local\root.crt .\native-root.crt
```

只复制公开 `root.crt`。`root.key` 留在 `F:\WeFlow-Test\pki` 内，**禁止导出、打包或交给客户端**。

```powershell
powershell -ExecutionPolicy Bypass -File .\central\windows-caddy\scripts\Test-NativeCaddyEndpoint.ps1 `
  -PackageRoot $PWD -NativeEnvPath .\native.env -CaCertPath .\native-root.crt
```

要求：

- **正常验证 TLS**：脚本强制要求 `-CaCertPath`，没有跳过校验的开关；**禁止 `--insecure`**；
- 后端顺序：`curl.exe --cacert <root.crt> --resolve <host>:443:<bindIp>` 优先；
  schannel 对内部 CA 报「吊销状态未知」（curl 退出码 60 且 stderr 含 revocation）时，
  判定该后端不适用并回落 **Python 标准库**（`create_default_context(cafile=...)` +
  `check_hostname=True` + `CERT_REQUIRED` + `server_hostname=<host>`，即完整链 + 主机名校验）；
  HTTP 响应由标准库 `http.client` 解析（支持 `Content-Length` 与 chunked，设 1 MiB 响应体上限），
  TLS 版本与密码套件在连接关闭前取得；
- **不改 DNS / hosts / NRPT**：域名映射只通过本次连接的 `--resolve` / `server_hostname` 完成；
- 退出码：`0` 通过；`1` 参数或配置错误；`3` 无可用后端；`4` TLS 校验失败；`5` 连接失败；
  `6` HTTP 非 200；`7` 响应契约不匹配（含 JSON 非法、缺字段、字段类型错误、协议版本不符）；
  **`8` 来源门禁拒绝（403，不算通过）**；`9` 响应协议错误（畸形 / 截断 / 超出大小上限）；
- 启动验收与本节诊断**共用同一份判定实现**（`Invoke-WeFlowEndpointAcceptance`），不存在两套阈值；
- 本阶段**不安装系统根信任**、**不修改客户端 hosts**；
- curl/Python 的默认测试只证明**证书链与主机名**，**不主张已完成吊销检查**；
- **本机探测的 `peer_ip` 不证明真实来源**：Python 后端输出里的 `peer_ip` 是「这次连接连到的服务器地址」
  （在本机自测时就是 `WEFLOW_NATIVE_BIND_IP` 本身），**不能**当作「Caddy 看到了真实 LAN 客户端来源」的证据；
  本机 Python 探测通过**不等于**第二台 LAN 客户端验收通过，第二台客户端（`192.168.1.53`）仍需按 §1 采样验证；
- Schannel（Windows 原生栈）与 Electron 客户端验收**仍需另行执行**，不能相互替代。

### 5.4 契约守卫

```powershell
powershell -ExecutionPolicy Bypass -File .\central\windows-caddy\scripts\Test-DeploymentContract.ps1 `
  -PackageRoot $PWD -NativeEnvPath .\native.env
```

未切换、只想预演时加 `-SkipRuntimeChecks`。它会断言模板语义、参数取值、脚本安全边界、交付包内容，

### 5.4.1 隔离测试入口（不部署、不改系统）

```powershell
# 1) PowerShell 隔离测试（真实调用生产脚本逻辑；叶子级系统调用全部 mock）
powershell -NoProfile -ExecutionPolicy Bypass -File .\central\windows-caddy\scripts\WeFlowNative.Tests.ps1

# 2) Python 端点后端测试（真实 http.client/TLS 解析路径；用一次性自签名证书在回环端口自测）
python .\central\windows-caddy\scripts\WeFlowNative.HttpsProbe.Tests.py
```

真实调用生产脚本与公共逻辑；打开公共模块的「测试模式」后，所有叶子级系统调用都被 mock 拦截，
**未替换的危险调用直接失败**，文件类操作被限制在本目录的沙箱内。全部用例通过时退出码为 0。
正常部署流程不会加载任何 mock，也不会打开测试模式。

`WeFlowNative.Tests.ps1` 的最后一个用例（**O. 真实参数回显子进程**）是**Windows 专属**：
它会用生产代码真实 `CreateProcess` 一次，只启动一个**无害的 PowerShell 回显子进程**，
逐值核对含空格 / 引号 / 反斜杠的参数是否原样到达；不启动 Caddy、不启动 Docker、不监听端口。
非 Windows 平台（或找不到 Windows PowerShell 5.1）时该用例记为 **SKIP**，不计入通过。
`Test-DeploymentContract.ps1` 的静态断言要求 `WeFlowNative.HttpsProbe.py` 一并随包交付。

### 5.5 停止与回退

```powershell
# 只停原生进程
powershell -ExecutionPolicy Bypass -File .\central\windows-caddy\scripts\Stop-NativeCaddy.ps1 `
  -PackageRoot $PWD -ReleaseDir <现有 Central 发布目录> -NativeEnvPath .\native.env

# 停原生进程并恢复原容器 caddy
powershell -ExecutionPolicy Bypass -File .\central\windows-caddy\scripts\Stop-NativeCaddy.ps1 `
  -PackageRoot $PWD -ReleaseDir <现有 Central 发布目录> -NativeEnvPath .\native.env -RestoreContainer
```

停止脚本只结束 `state\native-caddy.current.json` 里记录的**精确 PID**，且会核对 PID 的可执行路径与
启动时间都与本轮记录一致（PID 复用一律拒绝），**结束之后还会确认进程确实消失**；
**绝不执行 `taskkill /IM caddy.exe` 这类按映像名宽泛杀进程**。恢复只执行 `start caddy`。
退出码：`0` 完成；`1` 参数/前置条件失败；`2` 身份不符或无法确认已退出（拒绝结束、保留记账）；
`3` 恢复容器失败（保留状态）；`4` 无可用的切换前记录。

回退**不会**删除数据库或 CA 卷：PostgreSQL 卷 `weflow-test_weflow-postgres` 与 Caddy 的

## 6. 安全边界（脚本强制，非建议）

| 边界 | 落地方式 |
|---|---|
| 只监听配置的物理 IPv4 | `bind {$WEFLOW_NATIVE_BIND_IP}`，渲染时替换；通配地址在参数校验阶段直接失败 |
